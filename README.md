# ระบบใบเสนอราคาและใบแจ้งหนี้

ระบบจัดการเอกสารสำหรับธุรกิจขนาดเล็ก ใช้ Next.js (App Router) และ Tailwind CSS
เก็บข้อมูลในไฟล์ SQLite บนเครื่อง ไม่ต้องใช้ Docker, Supabase หรือบริการภายนอกใด ๆ

## เริ่มใช้งาน

ต้องมี Node.js 22.18 ขึ้นไป (แนะนำ Node 24) ใช้ SQLite ที่มากับ Node (`node:sqlite`) จึงไม่ต้องติดตั้งฐานข้อมูลเพิ่ม

```bash
npm install
npm run dev         # http://localhost:3000
```

เข้าสู่ระบบด้วยบัญชีทดลอง **demo@example.com / demo1234**

ครั้งแรกที่เปิดแอป ระบบจะสร้างไฟล์ `data/app.db` และใส่ข้อมูลตัวอย่างให้อัตโนมัติ
(บริษัท 1 แห่ง ลูกค้า 5 ราย สินค้า 8 รายการ เอกสาร 14 ใบ โดยวันที่อิงจากวันที่สร้างฐานข้อมูล)

## คำสั่ง

| คำสั่ง | หน้าที่ |
| --- | --- |
| `npm run dev` | รันแอปโหมดพัฒนา |
| `npm run build` / `npm run start` | build และรันแบบ production |
| `npm run db:reset` | ลบ `data/app.db` แล้วสร้างใหม่พร้อมข้อมูลตัวอย่าง (หยุดแอปก่อน) |
| `npm test` | ทดสอบการคำนวณยอดเงิน จำนวนเงินเป็นตัวอักษร และกฎของเอกสาร |
| `npm run lint` | ตรวจโค้ดด้วย ESLint |

> ชื่อโฟลเดอร์มีเครื่องหมาย `&` ซึ่งทำให้ไฟล์ `.cmd` ใน `node_modules/.bin` ทำงานไม่ได้บน Windows
> ดังนั้น `npx next ...` จะล้มเหลว ให้ใช้ `npm run` ด้านบนแทน

## โครงสร้าง

```
app/(app)/               หน้าที่ต้องล็อกอิน: ภาพรวม, documents, billing-notes, receipts, tax-invoices, customers, products, company
app/login/               หน้าเข้าสู่ระบบ
app/print/                หน้าเอกสาร A4 สำหรับพิมพ์และบันทึก PDF ([id] = QT/IV, billing/[id] = ใบวางบิล, receipt/[id] = ใบเสร็จ, tax-invoice/[id] = ใบส่งของ/ใบกำกับภาษี)
proxy.ts                 ส่งผู้ที่ยังไม่มี session cookie ไปหน้า /login
components/              ฟอร์ม, Document Builder, ปุ่มสถานะเอกสาร, กราฟ
lib/auth.ts              อ่าน session ของผู้ใช้ (requireUser)
lib/data.ts              ฟังก์ชันอ่านข้อมูลสำหรับหน้าเว็บ ตรวจ session ทุกครั้ง
lib/actions.ts           Server Actions สำหรับบันทึกข้อมูล
lib/calc.ts              คำนวณยอดเงิน ใช้ร่วมกันทั้งหน้า Builder และตอนบันทึก
lib/server/db.ts         เปิดไฟล์ SQLite และสร้างตาราง
lib/server/store.ts      คำสั่งอ่าน/เขียนข้อมูลและกฎของเอกสารทั้งหมด
lib/server/seed.ts       ข้อมูลตัวอย่างและบัญชีทดลอง
lib/server/users.ts      ผู้ใช้และ session ของระบบล็อกอินจำลอง
```

ตารางในฐานข้อมูล: `companies`, `customers`, `products`, `documents`, `document_items`,
`billing_notes`, `billing_note_items`, `receipts`, `receipt_items`, `tax_invoices`, `document_sequences` (ตัวนับเลขเอกสาร), `users`, `sessions`
เปิดดูไฟล์ `data/app.db` ได้ด้วยโปรแกรมอย่าง [DB Browser for SQLite](https://sqlitebrowser.org/)

## กฎของเอกสาร

กฎเหล่านี้อยู่ใน `lib/server/store.ts` และทุกการบันทึกต้องผ่านไฟล์นี้

- **เลขที่เอกสาร** ออกอัตโนมัติเมื่อบันทึก รูปแบบ `QT202611-001` นับใหม่ทุกเดือนแยกตามประเภท โดยใช้เดือนจากวันที่เอกสาร (ปี ค.ศ.)
- **สถานะ:** `draft → sent → approved → paid` และยกเลิกได้ก่อนชำระ ใบแจ้งหนี้เป็น `paid` เมื่อออกใบเสร็จรับเงิน (ข้ามจาก `sent` ได้) ส่วนใบเสนอราคาไม่มีสถานะ `paid` เอกสารที่ `cancelled` เปลี่ยนต่อไม่ได้ และ `paid` จะกลับได้เฉพาะเมื่อยกเลิกใบเสร็จ
- **การแก้ไข:** แก้ได้เมื่อสถานะเป็นร่าง ส่งแล้ว หรืออนุมัติแล้ว (ปุ่ม **แก้ไข** ในรายการและหน้าเอกสาร) โดยเลขที่และสถานะไม่เปลี่ยน แก้ไม่ได้เมื่อชำระแล้ว ยกเลิกแล้ว หรือเป็นใบเสนอราคาที่แปลงเป็นใบแจ้งหนี้แล้ว (ให้แก้ที่ใบแจ้งหนี้แทน) กฎนี้อยู่ใน `lib/document-rules.ts`
- **การลบ:** เอกสารไม่มีการลบ มีแต่ยกเลิก เพื่อให้เลขที่เอกสารไม่หายไป
- **แปลง QT เป็น IV:** ทำได้เมื่ออนุมัติแล้ว ได้ใบแจ้งหนี้ร่าง โดยวันครบกำหนดคำนวณจากเครดิตเทอมของลูกค้า และแต่ละ QT มีใบแจ้งหนี้ที่ยังไม่ถูกยกเลิกได้ใบเดียว
- **ยอดเงิน:** VAT คิดเฉพาะรายการที่คิด VAT, หัก ณ ที่จ่ายคิดจากยอดก่อน VAT, ยอดสุทธิ = ยอดรวม + VAT − หัก ณ ที่จ่าย ปัดเศษเป็นสตางค์
- **ภาพรวม:** ยอดขาย = ยอดก่อน VAT ของใบแจ้งหนี้ที่ออกแล้ว (`sent`, `approved`, `paid`) ตามเดือนของวันที่เอกสาร ส่วนยอดรอเก็บเงินและยอดเกินกำหนดเป็นยอดสุทธิของใบแจ้งหนี้ที่ยังไม่ชำระ

## ข้อมูลบริษัทผู้ออกเอกสาร

เมนู **ข้อมูลบริษัท** (`/company`) ใช้แก้ชื่อ ที่อยู่ เลขผู้เสียภาษี สาขา ติดต่อ โลโก้ และบัญชีรับชำระ
ระบบมีบริษัทผู้ออกเอกสารเพียงบริษัทเดียว และเอกสารทุกใบแสดงข้อมูลล่าสุดของบริษัทนี้ รวมถึงเอกสารที่ออกไปแล้ว
โลโก้ (PNG, JPG, WEBP, GIF หรือ SVG ไม่เกิน 500 KB) เก็บในฐานข้อมูลเป็น data URL ไม่ต้องมีที่เก็บไฟล์แยก

## ใบวางบิล

ใบวางบิลอยู่ในเมนู **เอกสาร** (ตัวกรองประเภท "ใบวางบิล" และปุ่ม **สร้างใบวางบิล**) ใช้รวมใบแจ้งหนี้ที่ยังไม่ชำระของลูกค้ารายเดียวกันไว้ในใบเดียวเพื่อนัดวันรับชำระ
เลขที่รูปแบบ `BL202611-001` สร้างจากหน้าใบแจ้งหนี้ได้ด้วย กฎอยู่ใน `lib/server/billing.ts` ส่วนรายการรวมทุกประเภทอยู่ใน `lib/server/document-list.ts`

- ใส่ได้เฉพาะใบแจ้งหนี้ที่ส่งแล้วหรืออนุมัติแล้ว (ยังไม่ชำระ) ของลูกค้ารายนั้น
- ใบแจ้งหนี้หนึ่งใบอยู่ในใบวางบิลที่ยังไม่ยกเลิกได้ใบเดียว การยกเลิกใบวางบิลจะทำให้นำใบแจ้งหนี้ไปวางบิลใหม่ได้
- ยอดเงินดึงจากใบแจ้งหนี้โดยตรง ถ้าแก้ใบแจ้งหนี้ ยอดในใบวางบิลจะเปลี่ยนตาม
- สถานะ: วางบิลแล้ว → ชำระครบแล้ว (เมื่อทุกใบในใบวางบิลชำระแล้ว) หรือยกเลิก แก้ไขได้จนกว่าจะยกเลิก

## ใบเสร็จรับเงิน

ใบเสร็จอยู่ในเมนู **เอกสาร** (ตัวกรอง "ใบเสร็จรับเงิน" และปุ่ม **ออกใบเสร็จรับเงิน**) เลขที่รูปแบบ `RC202611-001` กฎอยู่ใน `lib/server/receipts.ts`
การรับชำระทำผ่านการออกใบเสร็จ: ปุ่ม **รับชำระ / ออกใบเสร็จ** ในหน้าใบแจ้งหนี้ หรือในหน้าใบวางบิล (เลือกใบแจ้งหนี้ที่ค้างชำระในใบนั้นให้)

- ใบเสร็จหนึ่งใบรับชำระใบแจ้งหนี้ได้หลายใบของลูกค้ารายเดียวกัน ระบุวันที่รับเงิน วิธีชำระ (เงินสด โอน เช็ค อื่น ๆ) และเลขอ้างอิง
- เมื่อออกใบเสร็จ ใบแจ้งหนี้จะเปลี่ยนเป็น "ชำระแล้ว" ตามวันที่รับเงิน ใบแจ้งหนี้หนึ่งใบมีใบเสร็จที่ยังไม่ยกเลิกได้ใบเดียว
- ใบแจ้งหนี้ที่ชำระแล้วแต่ยังไม่มีใบเสร็จ ออกใบเสร็จย้อนหลังได้
- แก้ไขได้เฉพาะวันที่ วิธีชำระ เลขอ้างอิง และหมายเหตุ ถ้าต้องเปลี่ยนรายการใบแจ้งหนี้ ให้ยกเลิกแล้วออกใหม่
- ยกเลิกใบเสร็จแล้ว ใบแจ้งหนี้จะกลับเป็นสถานะก่อนรับชำระ (ใช้แก้กรณีบันทึกรับเงินผิด)

### ใบเสร็จรับเงิน/ใบกำกับภาษี

ถ้าเปิด **จดทะเบียนภาษีมูลค่าเพิ่ม** ในหน้าข้อมูลบริษัท (ค่าเริ่มต้น) ใบเสร็จที่ออกจะเป็นใบกำกับภาษีเต็มรูปด้วย
โดยพิมพ์รายละเอียดตามมาตรา 86/4 แห่งประมวลรัษฎากร: คำว่า "ใบกำกับภาษี", ชื่อ ที่อยู่ เลขผู้เสียภาษี และสาขาของผู้ขายและผู้ซื้อ,
เลขที่และวันที่, รายการสินค้า/บริการพร้อมจำนวนและมูลค่า และภาษีมูลค่าเพิ่มแยกจากมูลค่าสินค้า

- พิมพ์ได้ทั้ง ต้นฉบับ + สำเนา (ค่าเริ่มต้น หน้าละฉบับ), ต้นฉบับ หรือ สำเนา
- ข้อมูลผู้ขายและผู้ซื้อถูกบันทึกไว้ ณ วันที่ออก การพิมพ์ซ้ำจึงตรงกับต้นฉบับแม้แก้ข้อมูลบริษัทหรือลูกค้าภายหลัง
- วันที่ของใบกำกับภาษีแก้ไม่ได้ ถ้าผิดให้ยกเลิกแล้วออกใหม่ (ใบที่ยกเลิกยังเก็บไว้พร้อมตรา "ยกเลิก")
- ถ้าลูกค้ามีเลขผู้เสียภาษีแต่ไม่ได้ระบุสาขา ฟอร์มจะเตือนให้ระบุ "สำนักงานใหญ่" หรือ "สาขาที่ ..."
- การเปลี่ยนสถานะจดทะเบียนมีผลกับใบเสร็จที่ออกใหม่เท่านั้น

### ใบส่งของ/ใบกำกับภาษี (ออกเมื่อส่งมอบสินค้า)

การขายสินค้ามีจุดความรับผิดทาง VAT เมื่อส่งมอบ ซึ่งมักเกิดก่อนรับเงิน ในหน้าใบแจ้งหนี้ (ส่งแล้ว อนุมัติแล้ว หรือชำระแล้ว)
กดปุ่ม **ส่งมอบสินค้า / ออกใบกำกับภาษี** ใส่วันที่ส่งมอบ แล้วจะได้ใบส่งของ/ใบกำกับภาษีเลขที่ `TX202611-001`
(อยู่ในหน้าเอกสาร ตัวกรอง "ใบกำกับภาษี") กฎอยู่ใน `lib/server/tax-invoices.ts`

- ใบแจ้งหนี้หนึ่งใบมีใบกำกับภาษีที่ยังไม่ยกเลิกได้ใบเดียว และวันที่ส่งมอบต้องไม่ก่อนวันที่ใบแจ้งหนี้และไม่เป็นวันในอนาคต
- ข้อมูลผู้ขายและผู้ซื้อถูกบันทึก ณ วันที่ออก ใบกำกับภาษีแก้ไขไม่ได้ ถ้าผิดให้ยกเลิกแล้วออกใหม่ พิมพ์ได้ทั้งต้นฉบับและสำเนา
- ระหว่างที่มีใบกำกับภาษี ใบแจ้งหนี้จะแก้ไขหรือยกเลิกไม่ได้ (ยกเลิกใบกำกับภาษีก่อน)
- ใบเสร็จของใบแจ้งหนี้ที่มีใบกำกับภาษีแล้วจะเป็นใบเสร็จรับเงินธรรมดา (อ้างอิงเลขใบกำกับภาษี) เพื่อไม่ให้ออกใบกำกับภาษีซ้ำ
  และห้ามรวมใบแจ้งหนี้ที่มีกับที่ยังไม่มีใบกำกับภาษีในใบเสร็จเดียวกัน
- ใบแจ้งหนี้ที่ได้ใบเสร็จรับเงิน/ใบกำกับภาษีไปแล้ว จะออกใบส่งของ/ใบกำกับภาษีซ้ำไม่ได้

แนวทาง: ขายสินค้าให้ออกใบกำกับภาษีเมื่อส่งมอบ แล้วออกใบเสร็จเมื่อรับเงิน ส่วนงานบริการให้ออกใบเสร็จรับเงิน/ใบกำกับภาษีเมื่อรับเงินได้เลย
ระบบไม่ได้ตัดสินแทนว่ารายการใดเป็นสินค้าหรือบริการ ควรให้ผู้ทำบัญชีตรวจรูปแบบและขั้นตอนก่อนใช้งานจริง

## พิมพ์เอกสาร / บันทึกเป็น PDF

กดปุ่ม **พิมพ์ / PDF** ที่หน้าเอกสาร หรือลิงก์ **PDF** ในรายการเอกสาร ระบบจะเปิดหน้าเอกสารขนาด A4 (`/print/<id>`) ในแท็บใหม่
แล้วกด **พิมพ์ / บันทึก PDF** จากนั้นเลือกเครื่องพิมพ์ หรือเลือกปลายทาง "บันทึกเป็น PDF" (ชื่อไฟล์ตั้งตามเลขที่เอกสารให้อัตโนมัติ)

- ใช้การพิมพ์ของเบราว์เซอร์ ภาษาไทยจึงแสดงถูกต้องทุกตัวอักษร โดยไม่ต้องติดตั้งไลบรารี PDF
- มีจำนวนเงินเป็นตัวอักษร (`lib/bahttext.ts`) และช่องลงลายมือชื่อ
- เอกสารสถานะร่างหรือยกเลิกจะมีตราประทับ "ร่าง" / "ยกเลิก" กำกับ

## ระบบล็อกอินจำลอง

ใช้สำหรับทดลองบนเครื่องเท่านั้น: มีผู้ใช้ทดลองคนเดียวในตาราง `users` (รหัสผ่านเก็บแบบ scrypt hash)
เมื่อล็อกอินแล้วจะได้ session cookie แบบ httpOnly อายุ 7 วัน ทุกหน้าและทุก Server Action ตรวจ session ก่อนอ่านหรือเขียนข้อมูล
ยังไม่มีหน้าสมัครสมาชิก แยกสิทธิ์ผู้ใช้ หรือรีเซ็ตรหัสผ่าน ต้องเปลี่ยนเป็นระบบล็อกอินจริงก่อนเปิดให้คนอื่นใช้งานผ่านเครือข่าย

> `npm run start` (production) ตั้งค่า cookie เป็น `Secure` ซึ่งเบราว์เซอร์ยอมรับบน `http://localhost` ได้
> ถ้าเปิดผ่าน IP อื่นที่ไม่ใช่ HTTPS แล้วล็อกอินไม่ติด ให้ตั้ง `INSECURE_COOKIES=1` ก่อนรัน
